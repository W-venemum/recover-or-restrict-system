# Recover-or-Restrict System

A subscription revenue-recovery and trust/access decision engine. It decides,
per customer, whether to **RECOVER**, **INTERVENE**, **RESTRICT**, or
**SUSPEND**, and picks a next-best recovery action, using transparent,
deterministic, rules-based logic with weighted, recency-decayed risk scoring.

> Core financial, risk and decision logic is fully deterministic and
> explainable. It never depends on an LLM. Any AI is optional and used only for
> presentation text, with a deterministic fallback.

## Product principle

A single normal/transient payment failure must **not** automatically damage
trust or lead to restriction. Genuine failure → RECOVER; behavioural avoidance
→ RESTRICT/SUSPEND. Blacklisting is only ever a **recommendation** for human
review, never applied automatically.

## Monorepo layout

This is an npm-workspaces monorepo:

- `server/` — Node/TypeScript backend. The deterministic decision engine lives
  in `server/src/engine/` and the domain model in `server/src/domain/`.
- `web/` — React (Vite) merchant dashboard (added in a later feature).
- `data/` — SQLite database file (gitignored; generated by seed/migrations).

### The deterministic core (`server/src/engine`)

| Module | Responsibility |
| --- | --- |
| `classifier.ts` | Maps raw gateway failure codes/reasons to a `FailureClass` with confidence. |
| `risk.ts` | Weighted, recency-decayed risk score (0–100) with band, confidence, evidence. |
| `patterns.ts` | Behavioural pattern detectors (cancellation cycling, value extraction, etc.). |
| `decision.ts` | `RECOVER / INTERVENE / RESTRICT / SUSPEND` rules + next-best recovery action. |
| `accessState.ts` | Access state machine `ACTIVE → RECOVERY → GRACE → RESTRICTED → SUSPENDED` (+ blacklist recommendation flag). |
| `index.ts` | Pure `evaluateCustomer(...)` orchestrator returning a full explainable result. |

Every non-trivial output carries an `evidence[]` array of human-readable reasons
so decisions are transparent and audit-ready.

## Getting started

```bash
npm install          # install all workspaces
npm run build        # typecheck + compile the server workspace (strict mode)
npm test             # run the server unit tests (added in a later feature)
```

Copy `.env.example` to `.env` if you want to enable optional integrations; the
app runs in deterministic demo mode without any keys.
